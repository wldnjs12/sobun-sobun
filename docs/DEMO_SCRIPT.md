# 데모 시나리오 (빌드업데이 · 해커톤 발표 공통)

발표 담당: 김민준 (조작은 백업으로 지원 또는 도우현이 옆에서 대기)

## 준비물 체크리스트 (시연 30분 전)

- [ ] 시연용 계정/건물 인증 최소 2개 기기(또는 브라우저 2개 창)로 준비 — 실시간 갱신을 눈으로 보여주려면 필수
- [ ] 미리 만들어둔 "진행중 팟" 1개 + "빈 목록" 상태를 보여줄 여분 건물 1개 (없는 상태도 보여줄지 결정)
- [ ] 테스트용 영수증 이미지 1장 (실제 편의점/마트 영수증 사진, 금액이 잘 보이는 것)
- [ ] Wi-Fi 상태 확인 — 현장 Wi-Fi가 불안정할 수 있으니 개인 핫스팟 백업 준비
- [ ] **라이브 데모 실패 대비용 화면 녹화 영상** 1개 (최소한 핵심 플로우만이라도)

## 시연 순서 (약 3~4분 기준)

### 1. 문제 제기 (20~30초)

> "자취생 88%가 대용량 식재료를 사놓고 못 먹어서 버린 경험이 있다는 걸 저희 팀이 직접 43명한테 설문해서 확인했어요. 그런데 이웃이랑 나눠 사자니, 낯선 사람 만나는 게 부담스럽다는 응답이 1위(56%)였습니다."

### 2. 온보딩 데모 (20~30초)

- 화면에서 QR 스캔 → GPS 인증 → 건물 홈 진입까지 실제로 보여주기.
- 멘트: "건물에 있는 사람만 들어올 수 있게 QR이랑 위치를 같이 확인해요."

### 3. 팟 참여 + 실시간 갱신 (1분, 가장 중요한 파트)

- 화면 A(이미 만들어둔 팟 상세)와 화면 B(다른 기기)를 나란히 두고, B에서 참여 버튼을 누르는 순간 A의 1인당 금액이 실시간으로 줄어드는 걸 보여준다.
- 멘트: "제가 지금 참여하는 순간 옆 화면 금액이 바로 바뀌는 게 보이시죠? 이게 저희 핵심 기능이에요."

### 4. 정산 데모 (1분)

- 팟 마감 → 영수증 업로드(미리 준비한 사진) → OCR 인식 결과 확인 → 정산 결과 화면(절약액 강조)까지.
- 멘트: "영수증만 찍으면 자동으로 금액을 읽어서, 대표 수고비까지 반영한 1인당 금액이 바로 나와요. 혼자 샀으면 OOO원인데 지금은 OOO원, OO% 아꼈어요."

### 5. 픽업 안내 (10~15초)

- 픽업 화면 보여주며: "얼굴 마주칠 필요 없이 택배함이나 문고리로 완전 비대면으로 수령해요."

### 6. 비즈니스 모델 한 줄 (10~15초)

> "저희는 참여자한테는 수수료를 받지 않고, 실제 거래가 성사된 마트하고만 3~5% 제휴 수수료를 받는 구조예요."

### 7. 마무리 (10초)

> "소분소분으로 자취생들이 대용량을 부담 없이, 눈치 안 보고 나눠 살 수 있게 만들고 싶습니다. 감사합니다."

## 리스크 대응

| 상황 | 대응 |
| --- | --- |
| 실시간 갱신이 네트워크 문제로 안 보임 | 미리 녹화한 백업 영상으로 전환, "네트워크 상태에 따라 지연될 수 있다"고 짧게 언급 |
| OCR 인식 실패 | 수동 입력 fallback으로 자연스럽게 전환 — 오히려 "인식 실패해도 서비스가 멈추지 않는다"는 포인트로 활용 가능 |
| 질문이 기술 스택(Node.js vs Spring Boot 등)에 대해 나올 경우 | "사업계획서 예시는 Node.js였지만, 팀 역량에 맞춰 Spring Boot로 구현했다"고 짧게 답변 |

## 리허설 체크리스트 (10/2 예정)

- [ ] 전체 순서를 실제로 처음부터 끝까지 한 번 통으로 리허설
- [ ] 시간 재보기 (3~4분 목표, 초과 시 어느 파트를 줄일지 미리 정하기)
- [ ] 백업 영상이 실제로 재생되는지 확인
- [ ] 김민준 외 1명이 조작을 동시에 연습해서, 발표자가 말하는 동안 조작이 매끄럽게 이어지는지 확인
