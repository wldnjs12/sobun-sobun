# 데모 시나리오 (빌드업데이 · 해커톤 발표 공통)

> ⚠️ **기획 개편(2026-10-03)**로 전체 시나리오가 바뀌었습니다. QR 스캔 → 주소 검색+GPS, 최저가 조회 삭제, 커뮤니티 추가. 발표 담당은 그대로 **김민준**입니다.

발표 담당: 김민준 (조작은 백업으로 최지원 또는 도우현이 옆에서 대기)

## 준비물 체크리스트 (시연 30분 전)

- [ ] 시연용 건물 2개 이상(제니스빌 등) + 각 건물에 사용자 2~3명 준비 — 실시간 갱신·건물 격리를 눈으로 보여주려면 필수
- [ ] 서버 환경변수로 **데모 고정 좌표 모드**를 켜둘지/끌지 미리 정하기 (실내 Wi-Fi가 불안정하면 켜두는 걸 추천)
- [ ] 테스트용 영수증 이미지 1장
- [ ] Wi-Fi 상태 확인 — 현장 Wi-Fi가 불안정할 수 있으니 개인 핫스팟 백업 준비
- [ ] **라이브 데모 실패 대비용 화면 녹화 영상** 1개

## 시연 순서 (약 3~4분 기준)

### 1. 문제 제기 (20~30초)

> "인하대 근처 용현동·학익동엔 자취생뿐 아니라 다양한 주민들이 살아요. 대용량으로 사면 싼 생필품·가공식품도 혼자 다 쓰기엔 부담스러운데, 낯선 이웃 만나는 게 꺼려져서 못 나눠 산다는 응답이 1위였습니다."

### 2. 온보딩 데모 (30~40초)

- (대표 휴대폰) 주소 검색 → "제니스빌" 선택 → 건물 확인 화면("제니스빌 이웃으로 등록돼요") → 건물 방 입장까지 실제로 보여주기.
- 멘트: "주소로 건물을 한 번 등록해두면, 그 다음부턴 팟을 열거나 참여할 때마다 위치만 짧게 확인해서 같은 건물 사람인지 봐요."

### 3. 팟 참여 + 실시간 갱신 (1분, 가장 중요한 파트)

- [팟 열기] 버튼 → 백그라운드 GPS 통과 → "화장지 30롤" 팟 개설(총액, 기준가, 목표 인원, 수고비율).
- 화면 A(팟 상세)와 화면 B(다른 기기)를 나란히 두고, B에서 참여 버튼을 누르는 순간 A의 1인당 금액이 실시간으로 줄어드는 걸 보여준다.
- 멘트: "제가 지금 참여하는 순간 옆 화면 금액이 바로 바뀌는 게 보이시죠? 이게 저희 핵심 기능이에요."

### 4. 건물 격리 + GPS 실패 데모 (30~40초)

- (다른 건물 휴대폰) 다른 주소로 입장 → 제니스빌 팟·커뮤니티가 안 보임. 팟 링크로 직접 접근해도 거부되는 것 확인.
- (GPS 실패) 등록 건물과 다른 위치(또는 데모 좌표 조작)로 [참여] 시도 → "집에 돌아가서 다시 시도해 주세요" 안내와 진행 차단 확인.
- 멘트: "주소만으로는 거짓으로 등록할 수 있어서, 팟을 열거나 참여하는 실제 행동마다 위치를 한 번 더 확인해서 다른 건물 사람이 섞이기 어렵게 만들었어요."

### 5. 커뮤니티 데모 (30~40초)

- 커뮤니티 입장(GPS 확인) → "공구 제안" 카테고리로 "생수 같이 사실 분" 글 작성 → 다른 주민이 익명 댓글("이웃 1") → [이 품목으로 팟 열기] 버튼으로 팟 생성 화면 연결.
- 멘트: "제안 글이 올라오면 바로 팟으로 연결돼요. 글쓴이 말고는 전부 익명이라 부담 없이 제안할 수 있어요."

### 6. 정산 데모 (1분)

- 팟 마감 → 영수증 업로드(미리 준비한 사진) → OCR 인식 결과 확인 → 정산 결과 화면(절약액 강조 + 송금 링크 + "보냈어요").
- 멘트: "영수증만 찍으면 자동으로 금액을 읽어서, 대표 수고비까지 반영한 1인당 금액이 바로 나와요."

### 7. 픽업 안내 (10~15초)

- 픽업 화면 보여주며: "얼굴 마주칠 필요 없이 택배함이나 문고리로 완전 비대면으로 수령해요."

### 8. 비즈니스 모델 한 줄 (10~15초)

> "참여자한테는 수수료를 받지 않고, 실제 거래가 성사된 마트하고만 제휴 수수료를 받는 구조예요."

### 9. 마무리 (10초)

> "소분소분으로 인하대 근처 이웃들이 생필품·가공식품을 부담 없이, 눈치 안 보고 나눠 살 수 있게 만들고 싶습니다. 감사합니다."

## 리스크 대응

| 상황 | 대응 |
| --- | --- |
| 실시간 갱신이 네트워크 문제로 안 보임 | 미리 녹화한 백업 영상으로 전환 |
| OCR 인식 실패 | 수동 입력 fallback으로 자연스럽게 전환 — "인식 실패해도 서비스가 멈추지 않는다"는 포인트로 활용 |
| 실내 GPS가 안 잡힘 | 서버 데모 고정 좌표 모드를 미리 켜두거나, 창가·건물 입구 근처로 이동 |
| 주소 검색 API가 현장에서 장애 | Stub(데모 건물 목록) 폴백이 자동으로 동작하므로 평소처럼 진행, 질문 나오면 "실제 서비스에서는 행정안전부 도로명주소 API를 쓴다"고 짧게 답변 |
| 질문이 기술 스택에 대해 나올 경우 | "사업계획서 예시는 Node.js였지만, 팀 역량에 맞춰 Spring Boot로 구현했다"고 짧게 답변 |

- [ ] 시간 재보기 (3~4분 목표, 초과 시 어느 파트를 줄일지 미리 정하기 — 가장 먼저 줄일 후보는 "4. 건물 격리+GPS 실패" 데모)
