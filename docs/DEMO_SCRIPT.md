# 데모 시나리오 (해커톤 발표)

> 기준: 빌드업 데이 보완계획서(2026.10.03) + 2026-11 보완. 품목은 생필품 + 밀봉 가공식품, 범위는 건물 단위 격리. 제품 규칙은 [PRODUCT_SPEC.md](./PRODUCT_SPEC.md).

조작은 발표자 1명 + 옆에서 백업 조작 1명.

## 준비물 체크리스트 (시연 30분 전)

- [ ] 서버 환경변수 결정: `DEMO_SEED=true`(시연용 건물·좌표 + "화장지 30롤"·"생수 2L×24병" 팟 생성), 실내 GPS가 불안정하면 `LOCATION_CHECK_DEMO_MODE=true`, 주소 API 장애 대비 `ADDRESS_DEMO_FALLBACK=true`. **시연이 끝나면 모두 false로 되돌린다.**
- [ ] 시연용 계정 3개 미리 가입: `demo1`·`demo2`는 **같은 건물**, `demo3`는 **다른 건물**. 예전 `?user=2` 방식은 없어졌으니 브라우저(또는 시크릿 창)마다 다른 계정으로 로그인한다.
- [ ] 최소 한 건물은 **건물명 없는 빌라**(예: "인하로67번길 3")로 등록해 둔다.
- [ ] 테스트용 영수증 이미지 1장 (화장지·생수 영수증)
- [ ] Wi-Fi 상태 확인 + 개인 핫스팟 백업
- [ ] **라이브 데모 실패 대비용 화면 녹화 영상** 1개

## 시연 순서 (약 3~4분 기준)

### 1. 문제 제기 (20~30초)

> "화장지 30롤, 생수 24병. 대용량이 싼 건 다 아는데, 혼자 사는 사람한테는 너무 많고 둘 데도 없어요. 설문에서도 낯선 이웃과 만나는 부담이 공동구매를 망설이는 이유 1위였어요. 그래서 같은 건물 이웃끼리, 뜯지 않은 그대로 나눠 갖게 만들었어요."

### 2. 가입·온보딩 (30~40초)

- 회원가입 → 주소 검색 "인하로67번길" → 도로명·지번이 같이 보이고 [더 보기]로 다음 결과 → 건물명 없는 빌라 선택 → 상세주소 "302호"("이웃에게는 보이지 않아요") → 건물 홈.
- 멘트: "주소는 한 번만 등록하고, 호수는 저만 봐요. 같은 건물 사람끼리만 서로의 팟과 글이 보여요."

### 3. 팟 개설 + 실시간 참여 (1분, 가장 중요한 파트)

- [팟 열기] → GPS 통과 → 카테고리 "휴지·물티슈", "코스트코 화장지 30롤", 총 30롤 · 1인 10롤 · 3명, 수고비 5%, 픽업 안내 "1층 공동현관 앞".
- 화면 A(대표 팟 상세)와 화면 B(`demo2`, 같은 건물)를 나란히 두고, B에서 건물 홈 → 카테고리/검색으로 찾기 → [참여하기]. A의 참여 인원과 1인당 금액이 바로 바뀌는 걸 보여준다.
- (시간 되면) 시드 팟 "생수 2L×24병, 1인 6병 1팩"도 보여주며: "생수·라면처럼 밀봉된 상온 제품도 돼요. 식재료는 위생·보관 문제로 안 받아요."
- 멘트: "제가 참여하는 순간 옆 화면 금액이 바로 바뀌죠? 그리고 저는 10롤을 뜯지 않은 그대로 받아요."

### 4. 건물 격리 + GPS 실패 (30~40초)

- (`demo3`, 다른 건물) 건물 홈에 방금 팟이 안 보임. 팟 링크로 직접 들어가도 "다른 건물의 팟에는 접근할 수 없어요".
- (GPS 실패) 등록 건물과 다른 위치에서 [참여하기] → "집에 돌아가서 다시 시도해 주세요" 시트, 진행 차단.
- 멘트: "주소만으로는 거짓 등록이 가능해서, 팟을 열거나 참여하는 순간마다 위치를 한 번 더 확인해요."

### 5. 건물별 익명 커뮤니티 (30초)

- 커뮤니티 입장(GPS) → "공구 제안"으로 "생수 2L 24병 같이 나누실 분?" → 다른 계정이 댓글("이웃 1") → [이 품목으로 팟 열기].
- 멘트: "글쓴이 말고는 전부 '이웃 N'으로만 보이고, 신고가 3번 쌓이면 자동으로 숨겨져요."

### 6. 정산 (1분)

- [모집 마감] → 영수증 업로드 → OCR 인식 → 송금 링크 붙여 확정 → 참여자 화면 "1인당 N원 송금해주세요" → [보냈어요].
- 멘트: "영수증만 찍으면 금액을 읽어서, 대표 수고비 5%까지 반영한 1인당 금액이 바로 나와요."

### 7. 픽업 (10~15초)

- 4자리 PIN, "1층 공동현관 앞", "뜯지 않은 상태 그대로인지 확인" → [수령 완료].

### 8. 비즈니스 모델·마무리 (20초)

> "참여자한테는 수수료를 받지 않고, 실제 거래가 성사된 마트와의 제휴 수수료를 목표로 해요. 소분소분으로 같은 건물 이웃들이 필요한 만큼만, 부담 없이 나눠 살 수 있게 만들고 싶습니다. 감사합니다."

## 최소 흐름 대체 계획 (라이브가 흔들릴 때)

순서대로 내려가며, 되는 단계까지만 보여준다.

1. 가입·주소 검색 생략 → 미리 로그인해 둔 `demo1`(시드 건물)로 바로 건물 홈.
2. 시드 팟 "화장지 30롤"에 `demo2`로 참여 → 실시간 금액 변화(핵심 장면).
3. 마감 → 정산은 OCR 대신 **금액 직접 입력**으로 확정.
4. 송금 링크·[보냈어요] → 픽업 PIN → [수령 완료].
5. 그래도 안 되면 녹화 영상으로 전환.

## 리스크 대응

| 상황 | 대응 |
| --- | --- |
| 실시간 갱신이 네트워크 문제로 안 보임 | 새로고침으로 최신 금액 확인 → 안 되면 녹화 영상 |
| OCR 인식 실패 | 수동 입력으로 전환 — "인식 실패해도 서비스가 멈추지 않는다"는 포인트로 활용 |
| 실내 GPS가 안 잡힘 | `LOCATION_CHECK_DEMO_MODE=true` 또는 창가·건물 입구로 이동 |
| 주소 검색 API 장애 | `ADDRESS_DEMO_FALLBACK=true`면 데모 건물 목록으로 진행. 질문 나오면 "실서비스는 행정안전부 도로명주소 API" |
| 로그인이 풀림 | 미리 적어둔 데모 계정으로 바로 재로그인 |
| "식품은 돼요?" 질문 | "생수·라면처럼 밀봉된 상온 제품은 미개봉으로 나눠요. 식재료 소분은 위생·보관 리스크가 커서 다루지 않아요" |
| "왜 같은 건물만?" 질문 | "엘리베이터만 타면 되니 이동 부담이 없고, 비대면 픽업이 자연스러워요. 인접 건물 확장은 다음 단계예요" |
| 기술 스택 질문 | "사업계획서 예시는 Node.js·Socket.io였지만, 팀 역량에 맞춰 Spring Boot + STOMP로 구현했다" |

- [ ] `demo1`·`demo2` 같은 건물, `demo3` 다른 건물인지 확인
- [ ] 시간 재보기 (3~4분 목표, 가장 먼저 줄일 후보는 "4. 건물 격리+GPS 실패")
- [ ] 시연 후 데모 플래그 3개 false로 복구
