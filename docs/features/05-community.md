# ⑤ 건물별 익명 커뮤니티 (신규)

담당: 김민준(백엔드 + 프론트, 단독) · 관련 화면: [S16~S18](../DESIGN_HANDOFF.md)

> 기존 ④최저가 조회를 대체하는 신규 필수 기능입니다. 최저가처럼 백엔드+프론트를 혼자 담당합니다 — [REPLAN_WORK_ASSIGNMENT.md](../REPLAN_WORK_ASSIGNMENT.md) 참고. **선행 조건**: 최지원의 ①(`User` 엔티티, `BuildingAccessService`)이 먼저 머지되어야 글쓴이의 건물 소속을 확인할 수 있습니다.

## 왜 필요한가 (근거)

접촉 부담(56%)이 가장 큰 망설임 이유였는데, 공동구매를 처음 제안하는 사람 입장에서도 "내가 먼저 나서는 게 부담스럽다"는 진입장벽이 있다. 완전 익명 커뮤니티로 "공구 제안"을 먼저 가볍게 던져볼 수 있게 하고, 반응이 괜찮으면 바로 팟으로 연결한다.

## 사용자 시나리오

1. 건물 홈 하단 탭에서 "커뮤니티"로 이동 → GPS 재확인(`purpose=COMMUNITY_ENTER`) 통과.
2. 카테고리(자유/질문/나눔/공구 제안)별 글 목록을 본다. 작성자는 "글쓴이"만 빼고 전부 "이웃 N"으로 익명 표시.
3. 글을 쓰거나 댓글을 단다. "공구 제안" 글에는 [이 품목으로 팟 열기] 버튼이 있어 누르면 팟 생성 화면(②)으로 넘어간다(상품명 미리 채움, GPS 재확인 한 번 더 거침).
4. 부적절한 글/댓글은 신고할 수 있고, 신고가 3회(임시값) 누적되면 자동으로 숨겨진다.

## 비즈니스 규칙

- **익명화는 저장하지 않고 응답 조립 시점에 계산**: 글쓴이는 항상 "글쓴이", 그 외 작성자는 그 글 안에서 첫 등장 순서대로 "이웃 1", "이웃 2"... 같은 사람은 같은 글 안에서 항상 같은 번호.
- 실제 `authorUserId`는 신고 처리용으로만 서버 내부에 보관하고, **API 응답에는 절대 포함하지 않는다.** 이 사실은 이용 안내에 고지해야 한다(기획수정_프롬포트.md 1-5절).
- 신고 자동숨김 기준: 3회(임시값, [open-decisions.md](../open-decisions.md)).
- 본인 글/댓글만 삭제 가능.
- 다른 건물 글/댓글에는 목록·상세·작성·댓글·신고 모두 403.
- 카테고리는 임시 목록(자유/질문/나눔/공구 제안) — 최종 확정 전까지 enum으로 분리해 구현.

## 엣지 케이스

- 같은 사용자가 같은 글을 여러 번 신고 → 중복 신고로 카운트되지 않게(유니크 제약).
- 글쓴이 본인이 자기 글에 댓글을 다는 경우 → "이웃 N"이 아니라 "글쓴이"로 표시(번호 부여 대상에서 제외).
- 공구 제안 글의 작성자가 글을 삭제했는데 이미 팟이 만들어진 경우 → 팟은 그대로 유지(글-팟 간 FK 없음, 생성 시점에 상품명만 복사해감).

## QA 체크리스트

- [ ] 글 상세 응답에 실제 `authorUserId`가 노출되지 않는가
- [ ] 같은 글 안에서 같은 작성자가 항상 같은 "이웃 N" 번호를 받는가
- [ ] 신고 3회 누적 시 목록/상세에서 자동으로 빠지는가
- [ ] 다른 건물 사용자가 postId로 직접 접근 시 403이 나는가
- [ ] "공구 제안" 글 → 팟 생성 화면 연동 시 상품명이 잘 전달되는가
