# ③ 대표 수고비(정률) 반영 자동 정산식

담당: 문소원(백엔드) + 홍수진(프론트) · 관련 화면: [S8~S12](../DESIGN_HANDOFF.md)

## 왜 필요한가 (근거)

기존 오픈채팅 공동구매의 실패 원인 중 하나는 "정산 미회수" — 대표가 먼저 돈을 걷지 못하거나 정산이 불투명해 신뢰가 깨지는 것이었다. 소분소분은 (1) 영수증 OCR로 실제 구매 금액을 투명하게 확인하고, (2) 수고비를 정률로 자동 계산해 대표가 원가 초과 청구를 할 수 없게 시스템적으로 막는다.

## 사용자 시나리오

1. 대표가 팟을 마감하고 실제로 마트/온라인몰에서 구매한다.
2. 영수증 사진을 앱에 업로드한다.
3. 서버가 Naver Clova OCR로 영수증 금액을 인식한다.
4. 인식된 금액을 대표가 확인(또는 수정)하고 확정한다.
5. 확정된 금액 기준으로 `최종 금액 = 인식된 원가 × (1 + 수고비율)`을 계산해 참여자별로 나눈다.
6. 참여자는 정산 결과 화면에서 자신의 몫과 절약액을 확인하고, 토스페이먼츠/카카오페이 송금 링크로 대표에게 송금한다.
7. 대표는 픽업 장소를 안내하고, 원 포장을 나눈 라벨 사진을 공유한다.

## 비즈니스 규칙

```
최종 정산 금액 = 영수증 인식 금액(recognizedCost) × (1 + 수고비율)
1인당 금액 = 최종 정산 금액 / 확정 참여자 수
```

- OCR 인식이 실패하면(글자 흐림, 지원 안 되는 영수증 형식 등) **수동 입력 폼으로 자동 전환**해야 한다 — 이 fallback이 없으면 정산 전체가 막히므로 필수 요구사항.
- 대표가 실제 영수증 금액보다 높게 "확정"하려는 시도(수동 수정 시)를 어디까지 허용할지: 완전 자유 입력을 허용하되, UI에서 "영수증 인식 금액과 크게 다릅니다" 같은 경고를 띄우는 정도로 절충 가능.

## 결제 흐름 (참고)

- 실제 결제는 에스크로가 아니라 **토스페이먼츠/카카오페이의 송금 링크**를 활용한 방식으로 구현 (사업계획서상 에스크로는 "설계 방향"으로만 제시되어 있고 해커톤 MVP 범위는 송금 링크 연동).
- 참여자가 송금을 완료했는지는 자동 확인이 아니라 **참여자가 "보냈어요" 버튼을 눌러 자가 신고**하는 방식으로 단순화 가능 (실시간 계좌 조회 연동은 MVP 범위 밖).

## 엣지 케이스

- 영수증에 팟과 무관한 다른 물건이 섞여 있는 경우 → OCR은 총액만 인식하므로, 대표가 수동으로 팟 관련 금액만 분리 입력할 수 있어야 함.
- 참여자 일부가 끝까지 송금하지 않는 경우 → MVP 범위에서는 대표가 직접 리마인드하는 정도로 충분 (독촉 알림 자동화는 확장 기능).
- 수고비율이 0%인 팟(대표가 순수 봉사로 진행) → 계산식이 정상 동작해야 함(경계값 테스트).

## QA 체크리스트

- [ ] OCR 인식 성공 시 화면에 정확한 금액이 자동으로 채워지는가
- [ ] OCR 인식 실패 시 수동 입력 폼이 자동으로 뜨는가
- [ ] 수고비율 0%, 참여자 1명 등 경계값에서 계산이 깨지지 않는가
- [ ] 정산 결과 화면의 "절약액"이 팟 상세(S6)에서 보여준 예상 절약액과 일관성 있게 표시되는가
