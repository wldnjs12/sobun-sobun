# ④ 최저가 조회 기반 상품 리스트 제공

담당: 김민준(백엔드) + 도우현(프론트) · 관련 화면: [S13](../DESIGN_HANDOFF.md)

다른 3개 기능과 달리 실시간 로직이 없는 **독립 모듈**이라, 초보 팀원 학습용 첫 기능으로 적합합니다.

## 왜 필요한가 (근거)

대표가 팟을 만들기 전 "이 상품을 어디서 사는 게 가장 싼지" 판단할 근거가 없으면 가격 비교 없이 임의로 상품을 고르게 되고, 참여자 입장에서도 "정말 싸게 사는 건지" 확신이 없다. 상품명을 입력하면 최저가를 자동 조회해줌으로써 팟 생성 전 의사결정을 돕고, 참여자에게는 "혼자 살 때 대비 얼마나 절약했는지" 계산의 기준값을 제공한다.

## 사용자 시나리오

1. 사용자가 상품명을 검색창에 입력한다 (예: "계란 30구").
2. 서버가 네이버 쇼핑 검색 API를 호출해 가격순으로 상위 결과를 가져온다.
3. 결과 리스트(상품명, 최저가, 판매처)를 보여준다.
4. 사용자는 결과에서 바로 "이 상품으로 팟 만들기"로 넘어갈 수 있다 (팟 생성 화면에 상품명/참고가가 미리 채워짐).

## 비즈니스 규칙

- 정렬 기준: 가격 오름차순.
- 상위 N개만 노출 (예: 5개) — 너무 많은 옵션은 선택 피로를 유발.
- 동일 검색어로 반복 조회 시 API 쿼터를 아끼기 위해 캐싱 고려 (해커톤 범위에서는 생략 가능, `Product` 엔티티가 캐시 용도로 이미 준비되어 있음).

## 엣지 케이스

- 검색 결과가 없는 경우 → "검색 결과가 없어요, 다른 검색어로 시도해보세요" 안내.
- 네이버 쇼핑 API 쿼터 초과/장애 시 → 사용자에게 "잠시 후 다시 시도해주세요" 안내, 팟 생성 자체는 최저가 조회 없이도 진행 가능해야 함(이 기능이 막혀도 핵심 플로우가 멈추면 안 됨).
- 검색어가 너무 짧거나 모호한 경우(예: "계란") → 결과가 너무 광범위할 수 있음, MVP에서는 별도 처리 없이 API 응답 그대로 노출.

## QA 체크리스트

- [ ] 정상 검색어에 대해 가격 오름차순으로 결과가 나오는가
- [ ] 검색 결과 없음 상태가 정상 표시되는가
- [ ] API 실패 시 다른 기능(팟 생성 등)에 영향 없이 에러만 격리되는가
- [ ] "이 상품으로 팟 만들기" 진입 시 팟 생성 화면에 값이 잘 전달되는가

## 발표 연계 메모

김민준은 발표도 담당하므로, 이 기능을 완성한 뒤 "왜 최저가 조회가 필요한지 → 실제 검색 데모 → 팟 생성으로 자연스럽게 연결" 흐름을 데모 시나리오에 넣으면 발표에서 보여주기 좋습니다.
