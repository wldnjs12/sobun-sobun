# ① QR+GPS 건물 인증 온보딩

담당: 문소원(백엔드) + 김민준(프론트) · 관련 화면: [S1~S3](../DESIGN_HANDOFF.md)

## 왜 필요한가 (근거)

자체 설문(자취생 43명)에서 이웃과 나눔에 대한 관심도는 평균 2.68/5로 낮은 편이었고, 망설이는 이유 1위는 **낯선 사람과의 접촉 부담(56%)**이었다. 이 문제를 풀기 위해 "같은 건물에 실제로 사는 사람"만 들어올 수 있게 QR+GPS 이중 인증으로 막고, 이후 흐름(픽업 등)도 비대면으로 설계한다.

## 사용자 시나리오

**정상 흐름**
1. 사용자가 건물 1층에 부착된 QR 코드를 스캔한다.
2. 앱이 QR에서 `qrToken`을 읽고, 동시에 GPS로 현재 좌표를 얻는다.
3. 서버에 `qrToken` + 좌표를 전송한다.
4. 서버는 QR 토큰이 유효한(만료 안 된) 건물의 것인지 확인하고, 건물 좌표 기준 반경 50m 이내인지 계산한다.
5. 통과하면 해당 건물에 인증된 상태로 홈(팟 목록)으로 이동한다.

**예외 흐름**
- QR이 만료된 경우 → "QR이 만료됐어요, 다시 스캔해주세요" 후 재스캔 유도.
- 반경 밖인 경우 → "건물 근처에서 다시 시도해주세요".
- 위치 권한을 거부한 경우 → 위치 권한이 왜 필요한지 설명 후 설정 화면 딥링크.
- 카메라 권한을 거부한 경우 → QR 대신 건물 코드를 직접 입력하는 대체 수단 고려 (MVP 범위 밖이면 "권한 허용 필요"만 안내).

## 비즈니스 규칙

- 허용 반경: **50m** (`ALLOWED_RADIUS_METERS`, `BuildingAuthService`에 상수로 존재).
- QR은 "동적 토큰" — 고정 QR이 캡처/공유되어 남용되는 것을 막기 위해 일정 주기로 토큰이 갱신되어야 한다 (구체 주기는 해커톤 범위에선 단순화 가능, 예: 매일 자정 갱신 또는 관리자가 수동 재발급).
- 거리 계산은 Haversine 공식 사용 (지구 곡률 고려한 두 좌표 간 거리).
- 인증에 성공하면 "사용자-건물 인증 기록"이 남아야 다음 방문 시 재인증 절차를 간소화할 수 있음 (예: 하루 한 번만 인증하면 유지).

## 엣지 케이스

- 같은 건물에 같은 사용자가 여러 번 인증 시도 → 중복 기록 방지 또는 최신 기록으로 갱신.
- GPS 오차가 큰 기기(실내 GPS 정확도 저하)에서 반경 판정이 애매한 경우 → 50m를 완전히 엄격하게 적용할지, 약간의 여유(buffer)를 둘지 팀 논의 필요.
- QR 코드가 훼손/오염되어 스캔이 안 되는 경우 → 재스캔 안내 외 별도 처리 없음(MVP 범위).

## 열려있는 질문

- QR 토큰 갱신 주기를 얼마로 할지 (해커톤 데모 때는 고정값이어도 무방).
- 인증 유효기간(하루/세션 단위/영구)을 어떻게 둘지 — 데모 편의상 세션 유지로 단순화 추천.
