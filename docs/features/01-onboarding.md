# ① 주소+GPS 건물 인증 온보딩

담당: 최지원(백엔드) + 도우현(프론트) · 관련 화면: [S1, S1-2, S2, S3](../DESIGN_HANDOFF.md)

> ⚠️ **기획 개편(2026-10-03)**: QR 인증을 완전히 없애고 "주소 입력(1차, 가입 시 1회) + GPS(2차, 행동 직전마다)"로 바꿨습니다. 과거 QR 버전은 [handoff/qr-auth.md](../handoff/qr-auth.md)에 기록으로만 남아있습니다. 담당자도 문소원·김민준 → **최지원·도우현**으로 바뀌었습니다 — 자세한 사유는 [REPLAN_WORK_ASSIGNMENT.md](../REPLAN_WORK_ASSIGNMENT.md).

## 왜 필요한가 (근거)

QR은 고정 QR이 캡처·공유되면 건물 밖 사람도 들어올 수 있다는 한계가 있었다. 주소는 자기 신고이고 GPS도 조작 가능하지만, "주소 등록 + 행동 시점마다 GPS 재확인" 조합이면 다른 건물 사람이 섞이기 훨씬 어려워진다. 접촉 부담이 가장 큰 망설임 이유(56%)였으므로, 인증 자체도 비대면으로 유지한다.

## 사용자 시나리오

**1차: 주소 입력 (가입 시 1회)**
1. 사용자가 도로명주소를 검색해서 고른다. 아파트면 동까지 고른다(호수는 받지 않음).
2. 서버가 주소를 정규화해 건물 키(`buildingKey` = `bdMgtSn` 또는 `bdMgtSn+동`)를 만들고, 좌표로 변환해 저장한다.
3. 같은 건물 키를 가진 사람끼리만 같은 건물 방에 들어간다.

**2차: GPS 확인 (팟 개설·참여·커뮤니티 입장 — 행동 직전마다, 캐시 없이 매번)**
1. 사용자가 해당 행동 버튼을 누르면, 화면 전환 없이 백그라운드에서 현재 위치를 받는다.
2. 서버가 등록된 건물 좌표와 거리를 계산(Haversine)하고, 허용 반경(100m, 임시값) 안이면 그대로 진행한다.
3. 반경 밖/권한 거부/타임아웃이면 각각 다른 안내와 함께 해당 행동을 막는다 (조회는 1차 인증만으로 허용).

## 비즈니스 규칙

- 허용 반경: **100m**(`LocationCheckService.ALLOWED_RADIUS_METERS`, 임시값 — [open-decisions.md](../open-decisions.md)).
- 거리 계산은 Haversine 공식, **반드시 서버에서 판정**(프론트 판정 결과를 신뢰하지 않음).
- GPS 판정 결과는 **캐시하지 않고 매번 재확인**(2026-10-03 확정).
- 위치 개인정보: 원본 좌표는 저장하지 않고, 판정 결과(성공/실패, 시각, 목적)만 `LOCATION_CHECK`에 기록.
- 다른 건물 리소스에 직접 접근 시 **403**(2026-10-03 확정).
- 시연 대비 데모 고정 좌표 모드: 서버 환경변수로만 켜짐, 기본 꺼짐.
- 서비스 지역 제한 없음(전국 허용, 2026-10-03 확정) — 단, 데모·초기 검증은 인하대 근처로.

## 엣지 케이스

- 같은 사용자가 이미 등록된 건물에 다시 주소를 등록하려는 경우 → find-or-create로 같은 건물에 묶임(건물이 새로 생기지 않음).
- 아파트 검색 결과에 동 목록이 없는 API 응답 → 직접입력 폼으로 폴백.
- 위치 권한 거부·타임아웃은 서버까지 가지 않고 **프론트 Geolocation 에러로 분기**(서버는 반경 밖만 판정).
