# 기획 개편 작업 분담 (2026-10-03~)

멘토링 이후 기획이 바뀌어 `기획수정_프롬포트.md`에 확정 기획을 정리했습니다. 이 문서는 "누가 뭘, 어떤 순서로" 만들지를 정리한 2차 작업 분담표입니다. 이 PR(문서 전용)이 develop에 머지되면 각자 자기 담당 브랜치를 새로 파서 바로 시작할 수 있습니다.

## 바뀌는 것 요약

- **삭제**: QR 인증 전체, 최저가 조회(④) 전체
- **신규**: 주소 입력(1차) + GPS 확인(2차, 행동 직전마다) 온보딩, 건물별 익명 커뮤니티(⑤)
- **변경**: 팟·정산·WebSocket에 "건물 소속 검증"(다른 건물 접근 403) 추가

근거/세부 규칙은 `기획수정_프롬포트.md` 1절, 계약(엔드포인트) 상세는 [API_SPEC.md](./API_SPEC.md), 데이터 모델은 [ERD.md](./ERD.md) 참고.

## 의존 순서

```
최지원 ①백(건물/주소/GPS/User엔티티/가드)
   ├─▶ 문소원 ③백 건물가드
   ├─▶ 김민준 ⑤커뮤니티 백
   └─▶ (②백 가드는 최지원 본인이 같이 작업)

도우현 ①프론트, 홍수진 디자인은 최지원 작업과 별개로 지금 바로 시작 가능
(단, 실제 API 연동은 최지원 PR 머지 후)
```

## 파일 소유권 (충돌 방지)

과거 세션에서 "같은 화면/엔드포인트를 동시에 두 명이 만드는" 충돌이 반복됐습니다(①③ 화면 중복, `GET /settlements/{podId}` 중복 구현). 이번엔 아래 기준으로 나눕니다.

- `backend/.../auth/**` — **최지원 전용**. 다른 사람은 PR 올리기 전에 먼저 pull 받아 최신 상태 확인.
- `backend/.../pod/**` — 최지원(가드 추가분만), 기존과 동일
- `backend/.../settlement/**` — 문소원 전용
- `backend/.../product/**` — **삭제 대상**. 김민준이 커뮤니티 PR에서 같이 지운다 (별도 삭제 PR 올리지 않음).
- `backend/.../community/**`(신규) — **김민준 전용**
- `frontend/src/features/onboarding/**` — 도우현 전용 (QrScanPage는 도우현이 자기 PR에서 삭제)
- `frontend/src/features/products/**` — **삭제 대상**. 김민준이 커뮤니티 프론트 PR에서 같이 지운다.
- `frontend/src/features/community/**`(신규) — 김민준 전용
- `frontend/src/features/settlement/**` — 홍수진(UI만), 로직 변경은 문소원과 상의
- `frontend/src/components/BottomNav.jsx`, `AppHeader.jsx` — 공용 컴포넌트라 **먼저 건드리는 사람이 팀 채팅에 알리기** (탭 구성이 `[팟/커뮤니티/내 팟/마이]`로 바뀌므로 도우현 또는 김민준 중 먼저 끝나는 쪽이 수정)

## 리뷰

기존 팀 룰(`CONTRIBUTING.md`) 그대로: 초보 팀원(김민준·도우현) PR은 최지원/문소원이 우선 리뷰.

## 임시값·확정 필요 항목

실제 구현에는 임시값을 상수로 넣어뒀습니다. 최종 확정은 [open-decisions.md](./open-decisions.md) 참고:
- GPS 허용 반경 100m
- 커뮤니티 신고 자동숨김 기준 3회
- 커뮤니티 카테고리(자유/질문/나눔/공구 제안)

아래는 이번에 확정해서 더 이상 "열린 질문"이 아닙니다 (구현 시 그대로 적용):
- 다른 건물 리소스 직접 접근 시 **403**
- GPS 통과 결과는 **캐시하지 않고 행동마다 매번 재확인**
- 주소 등록 가능 지역 **제한 없음**(전국)
- 아파트 "동"은 **주소 검색 결과 리스트에서 선택** (API가 동 목록을 안 주면 직접입력 폴백)
