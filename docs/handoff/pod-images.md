# 핸드오프: ② 팟 예시 사진 + 학교 시연 데이터

_최종 갱신: 2026-11-08 · 브랜치: feature/pod-example-images → feature/demo-script → feature/fee-label-no-emoji → feature/empty-slot-icon → feature/demo-script-refresh → feature/remove-ui-emoji → feature/demo-data-cleanup_

> **시연 대본·루트는 [../DEMO_SCRIPT.md](../DEMO_SCRIPT.md)** (2026-11-08 갱신). 노트북(sobun01, 대표) + 폰(sobun02, 참여자)이 키친타월 팟 하나로 개설 → 실시간 참여 → 정산 → 픽업까지 진행하는 3~4분 구성이다. 2026-11-08에 리허설 데이터를 재시드했다. 모집 중인 팟은 모집 취소하고 처음 상태(화장지 2/3 · 생수 2/4 · 세제 1/3 · 물티슈 3/5 · 컵라면 4/4)로 새로 만들었다. 리허설 때 마감된 옛 화장지 팟(id 1)은 [내 팟]에 기록으로만 남아 있다. 같은 날 밤 최신 main(#74, 상품 사진 업로드·이모지 제거·[+ 열기] 위치 이동)에 맞춰 대본을 다시 맞췄고, 리허설과 팀 테스트로 생긴 팟(하리보 id 11, 전민규 id 14, 티백 id 12·13)과 리허설 댓글 4개·신고 1건은 DB에서 지웠다. 연결된 참여·정산·사진 행도 함께 지웠다.

> **2026-11-08 추가: 대표가 실제 상품 사진을 올릴 수 있다** (브랜치 feature/pod-photo-upload, PRODUCT_SPEC D28).
> - 개설·수정 화면의 "상품 사진 (선택)"에서 1장. 프론트가 긴 변 800px JPEG로 줄여 `POST /api/pods/{id}/image`로 올리고, 서버는 `pod_image` 테이블(bytea)에 저장한다. `pod.image_version`이 null이 아니면 사진이 있다는 뜻.
> - 화면(건물 홈 카드·상세·내 팟·참여 확인 시트·모집 완료)은 `usePodPhoto(pod)` 훅 하나로 고른다: 올린 사진 → 아래 예시 사진 → 카테고리 아이콘.
> - 등록·교체·삭제는 글 수정과 같은 조건(대표 + 모집중 + 대표 외 참여자 없음), 조회는 같은 건물만.

## 이번 작업 요약
- 팟 카드(건물 홈)와 팟 상세 상단에 **품목별 예시 사진**을 표시한다. 팟에 사진 업로드 기능이 없어서 프론트가 사진을 고른다.
  - `podImage(pod)` (`frontend/src/features/pod/podApi.js`): 제목 키워드(물티슈·키친타월·생수·라면·세제·화장지·휴지) → 카테고리(TISSUE·LAUNDRY·KITCHEN) 순으로 고르고, 맞는 사진이 없으면 `null`을 돌려준다. 이때 화면에는 기존 카테고리 아이콘이 나온다.
  - 사진 6장: `frontend/public/pods/*.jpg`(500px). 모두 Wikimedia Commons의 자유 라이선스 사진이고, 출처는 같은 폴더 `CREDITS.md`에 있다.
- (코드 밖) 실서버에 학교 시연용 데이터를 넣었다. 대상은 "인하로 100" 건물(id 4)이다.
  - 시연 계정 6개: `sobun01`~`sobun06`. 비밀번호는 팀 채팅을 참고한다.
  - 팟 5개: 화장지·생수·세제·물티슈·컵라면. 컵라면 팟은 정원이 차 있어서 마감·정산 시연용이다.
  - 커뮤니티 글 4개 + 댓글.

- (2026-11-08) 화면 문구에서 장식용 이모지(⭐ ✨)를 뺐다. AI가 만든 티가 난다는 피드백 때문이다. 대상: 팟 개설의 수고비율 "추천" 라벨, 송금 확인 요청 완료 제목, 건물 확인 안내. 앞으로 화면 문구에는 이모지 대신 Material 아이콘(`Icon`)을 쓴다.
- (2026-11-08) 남은 이모지도 모두 뺐다. 모집 완료 화면 대표 카드는 Material 아이콘(flag·receipt_long·shopping_bag)으로 바꿨다. 커뮤니티 카테고리 칩·배지는 글자만 남겼다(카테고리별 색 배지는 그대로). 영수증 확인 화면의 머리말에서도 이모지를 뺐다. 랜딩 `/intro2`의 궤도·상자 그림은 아이콘으로 바꿨고, 띠 문구는 글자만 남겼다(구분자 ✦ → ·). `frontend/src`에 이모지는 하나도 남지 않았다.
- (2026-11-08) 팟 상세 참여 이웃 목록의 빈자리 아이콘을 `star`에서 `person_add`로 바꿨다. 별은 의미가 없고 장식처럼 보였는데, 사람 추가 아이콘은 "눌러서 참여"라는 뜻이 바로 보인다.

## 기획 대비 확인 (spec-check)
- 일치: PRODUCT_SPEC에 팟 사진 규칙이 없어서 충돌하는 부분이 없다. 품목도 생필품 + 밀봉 가공식품 범위다. 라면 사진은 조리된 사진 대신 포장 상태 사진을 썼다(미개봉 콘셉트).
- 의도적 단순화: 사진 업로드나 서버 저장 없이 프론트 정적 파일로만 처리했다. 이유는 마감(11/11) 직전이라 API·DB를 바꾸지 않기 위해서다.
- 재확인 필요: "인하로 100" 건물 이름이 처음 등록한 사람 기준인 "인하대,인하공전,정석항공고"로 저장돼 있다. 시연 전에 Supabase에서 `UPDATE building SET name = '인하대 60주년기념관' WHERE id = 4;`를 실행해야 한다.

## 알려진 제한사항 / TODO
- 사진은 제목과 카테고리로 추정한 **예시**일 뿐, 실제 상품 사진이 아니다. BATH·CLEANING·DAILY·ETC 카테고리는 사진이 없어서 아이콘이 나온다.
- 지오코딩 기준점(하이테크관 근처)에서 60주년기념관까지는 100m가 넘는다. 학교에서 시연하려면 Railway `LOCATION_CHECK_DEMO_MODE=true`가 필요하다. 시연이 끝나면 `false`로 되돌린다.

## 다음 작업자 안내
- 로컬: `cd frontend && npm run dev`. 홈에서 "화장지", "생수" 같은 제목의 팟 카드에 사진이 나오는지 확인한다. 빌드 확인은 `npm run build`.
- 사진을 추가하려면 `public/pods/`에 jpg를 넣고, `podApi.js`의 `IMAGE_BY_KEYWORD`나 `IMAGE_BY_CATEGORY`에 한 줄 추가한 뒤 `CREDITS.md`에 출처를 적는다.
