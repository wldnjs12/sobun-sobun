# GitHub Projects 칸반 보드 사용법

팀 할 일 관리는 GitHub Projects(칸반 보드)로 합니다. 이미 세팅은 끝나 있어서, 아래 사용법만 읽으면 바로 쓸 수 있어요.

- 보드 링크: https://github.com/users/wldnjs12/projects/1
- 저장소 `wldnjs12/sobun-sobun`에 연결되어 있어서, 이 저장소의 이슈/PR을 카드로 바로 가져올 수 있습니다.

## 1. 칼럼 구성

| 칼럼 | 의미 |
| --- | --- |
| Backlog | 아직 시작하지 않은 작업 |
| 진행중 | 현재 작업 진행 중 |
| 리뷰 | 리뷰 대기 중 (PR 올렸는데 아직 머지 전) |
| 완료 | 작업 완료됨 |

카드를 칼럼 사이로 드래그하면 그 카드(이슈/PR)의 `Status` 값이 자동으로 바뀝니다.

## 2. 자동으로 되는 것들 (이미 켜져 있음)

보드 우측 상단 **Workflows**에 기본으로 켜져 있는 자동화가 몇 가지 있어요. 팀원들이 따로 신경 안 써도 알아서 동작합니다.

- **이슈/PR을 보드에 추가하면 → 자동으로 Backlog 칼럼으로 들어감**
- **이슈나 PR을 닫으면(Close) → 자동으로 완료 칼럼으로 이동**
- PR이 머지되면 관련 워크플로우도 같이 동작해서 상태가 정리됩니다.

즉, PR 설명에 `Closes #12` 처럼 이슈 번호를 연결해두면, 그 PR이 머지될 때 연결된 이슈가 자동으로 닫히고 → 카드가 완료 칼럼으로 저절로 이동합니다. 이 조합을 쓰면 카드 옮기는 걸 거의 손으로 안 해도 돼요.

### (선택) 이슈/PR을 보드에 자동으로 추가하고 싶다면

지금은 이슈나 PR을 만들어도 자동으로 보드에 올라오지는 않아요(수동으로 추가해야 함). 매번 손으로 추가하는 게 귀찮으면:

1. 보드 우측 상단 `...` → **Workflows**
2. 왼쪽 목록에서 **Auto-add to project** 클릭 → 우측 상단 **Edit**
3. 필터에 `is:issue,pr is:open` 정도로 넣고 저장, 토글을 **On**으로 변경

이렇게 해두면 저장소에 새 이슈/PR이 생길 때마다 자동으로 보드(Backlog)에 들어옵니다. 팀 규모가 작아서 굳이 안 켜도 되지만, 편하려면 지원님이 한 번 켜두는 걸 추천해요.

## 3. 할 일을 카드로 만드는 법

두 가지 방법이 있어요.

**방법 A — 보드에서 바로 만들기 (간단한 할 일)**
1. 원하는 칼럼(예: Backlog) 맨 아래 `+ Add item` 클릭
2. 할 일 제목 입력하고 Enter

이렇게 만든 카드는 "초안 이슈(Draft issue)"라서 저장소 이슈랑 연결되어 있지 않아요. 가볍게 메모하듯 쓸 때 편합니다.

**방법 B — 저장소 이슈로 만들기 (코드 작업과 연결할 때 추천)**
1. 저장소에서 GitHub Issue를 하나 만든다 (제목 예: "QR 스캔 후 위치 검증 API 구현")
2. 이슈 우측 사이드바에서 **Projects** → `소분소분 개발 보드` 선택 → 보드에 자동으로 카드 생김
3. 담당자(Assignee)도 같이 지정해두면 보드에서 누가 뭘 하는지 한눈에 보임

기능 작업(ONBOARDING.md의 담당 업무표에 있는 것들)은 방법 B로, 이슈로 만들고 PR에서 `Closes #이슈번호`로 연결하는 걸 추천합니다. 그래야 머지될 때 자동으로 완료 처리돼요.

## 4. 화면 보기 전환

상단 탭 옆 **View** 버튼에서 **Table**(표 형태) / **Board**(칸반 보드) / **Roadmap**(일정 타임라인) 중 고를 수 있어요. 기본 보기는 Board로 맞춰뒀습니다. 상단 탭 이름이 마음에 안 들면 탭 옆 ▾ 화살표 → **Rename view**로 바꿀 수 있어요.

## 5. 검색/필터

보드 상단 `Filter by keyword or by field` 검색창에 `assignee:도우현` 처럼 입력하면 특정 담당자 카드만 볼 수 있고, `is:open` 등으로도 걸러집니다.
